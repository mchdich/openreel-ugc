# OpenReel implementation plan

> **For agentic workers:** Use superpowers:executing-plans or the independent task briefs below. Track verification with each task.

**Goal:** Release a runnable, independently written open source recreation of the Lightreel research experience.
**Architecture:** Browser modules share a corpus research engine with a Node/Worker API. All corpus data stays browser local unless sent explicitly in a research request. Server configuration optionally enables AI.
**Tech Stack:** Node 22+, browser ES modules, CSS, built-in node:test, Cloudflare Workers.
**Spec:** ../specs/2026-10-17-openreel-design.md

## Global constraints

- Zero runtime dependencies. No proprietary code/media/data in the release.
- Clearly distinguish fictional fixtures, imported data and configured AI.
- API keys stay server side. Publicly exposed paid AI requires a bearer token.
- Corpus-derived citations, metrics and matches only. Empty search stays empty.

## Review focus

- Creator min/max and university filters cannot return unrelated matches.
- Invalid imports preserve the existing library and reject unsafe links.
- User content is text, never executable markup.
- Corrupted browser storage recovers without a blank screen.
- Concurrent or failed research must leave the composer usable.

## Task 1: Research engine and API

Files: public/engine.js, lib/api.js, server.js, test/engine.test.js, test/api.test.js.
Produces: normalizeRecords(input) -> records; searchRecords(records,query,options) -> records; getTrends(records) -> grouped trends; research(records,question,history) -> {kind,title,summary,sections,sources,creators,stats}; handleApi(request,env) -> Response.

- [ ] Implement functions and Node routes. /api/chat accepts {question,records,history,mode}; /api/status returns provider availability without secrets.
- [ ] Test deterministic fallback and configured-provider error paths. Run suite green.
