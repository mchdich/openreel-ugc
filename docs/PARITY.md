# Full demo parity: evidence and remaining work

The target remains **full 1:1 parity with the observable March 2026 Lightreel demo**, including independently acquired real corpus coverage. The [continuation specification](superpowers/specs/2026-10-17-parity-continuation.md) supersedes earlier exclusions that treated live discovery, video understanding or corpus scale as outside scope. This implementation advances that target; it does not establish completion.

## References

The primary reference is the [March 16 launch post](https://x.com/Jibran_05/status/2033589137018917027): competitor hooks, video critique, constrained creator discovery and an advertised 150,000+ analyzed-video index. That advertised number is not an OpenReel dataset.

The later [website](https://lightreel.ai/) and [API documentation](https://lightreel.ai/docs), inspected October 17, 2026, inform navigation and source presentation. They do not prove every later feature appeared in the March demo. No Lightreel application source, private index, model weights or demo media is included.

## Recorded implementation evidence

- **Free creator acquisition:** known public handles yield bounded official embed snapshots locally. Fresh collection contributed 262 records to the hosted seed. Followers/views are observed where available; absent likes/comments/shares remain unknown. Bio emails and conservative school/city labels retain public self-description evidence. Cloud creator acquisition itself failed in the recorded check and is not counted as successful cloud live discovery.
- **Persistent indexing:** the [SQLite/D1 pipeline](CORPUS.md) exceeds the browser cap. The normal local product store combines 150,000 NC research records, 4,162 archival records and 262 fresh observations, all real-class: 154,424 total across 4,621 creator identities, with 262 provider-observed. At 2026-10-17T21:30:57.284Z the separate cloud seed held 4,424 real records across 2,755 creators, imported as `user-supplied` with `providerObservedReal: 0`. Those counts are not interchangeable.
- **Web-assisted discovery (1.7.0):** a model proposes at most three handles using one completed web-search result; up to three indexed profiles are also refreshed. Official public embeds alone supply records and eligibility facts. At least two coffee creators were absent by both handle and numeric creator ID before the first browser acquisition; the store grew from 154,424/4,621/262 to 154,428/4,624/266 (records/creator identities/provider-observed). Final coffee and NYU browser repeats passed with loaded avatars, reload and mobile checks. One incidental coffee caption no longer establishes a creator niche. This does not establish unrestricted discovery, current posting dates or representative coverage.
- **Query and acquisition resilience (1.7.1):** capitalized content topics no longer imply a school. Explicit institution searches preserve existing SQLite/D1 keys. A failed profile batch halts later acquisition, returning only confirmed fresh matches with an explicit partial-results notice. The actual browser retained three coffee creators and the compound NYU/contact match despite one failed check in each flow. No retry, stale fallback or access workaround was used.
- **Numeric identity and model descriptions:** strict official player URLs retain actual creator IDs and empty unknown usernames. Named/unnamed rows with the same creator ID group together; upstream descriptions never replace source transcripts. Native browser verification displayed and bookmarked actual source `tiktok-7386507456479825195`, then restored it after reload without inventing a username. Source labels and licenses survive the application path.
- **Bounded current refresh:** commit `ce6f9c6` filters genuine known JSON handles before SQL deduplication/limits, so numeric-only archival rows cannot consume profile-refresh slots. The actual local NYU three-profile refresh/browser research flow succeeds; hosted provider egress remains a separate failed check.
- **Actual local models:** the manual [CPU setup](LOCAL_MODELS.md) ran real Qwen2-VL vision and Whisper tiny.en speech. The actual app’s eight-frame plus audio browser path succeeded in 39,171 ms. Both direct WAV and extracted-MP4 speech checks matched all 27 reference words after punctuation/case normalization.
- **Source selection and continuity:** Video, Library, Live search and configured Corpus are explicit. Successful Video context supports in-memory follow-ups for at most two chats. Selecting another source does not silently reuse retained frames. Raw JPEG/WAV payloads do not persist.
- **Structured responses:** strict JSON Schema is the vision default; the optional legacy JSON-object mode still undergoes validation. An earlier actual model response with duplicate citations was correctly rejected. Passing the schema does not prove every visual interpretation is correct.
- **Dated format momentum (1.3.0):** explicit emerging/rising/gaining-share requests compare adjacent inclusive posting-calendar windows, defaulting to today and seven days. A positive signal requires five current clips, three current creator identities, prior evidence and an actual increase in the format’s share of all dated retrieved records. Invalid explicit dates/windows fail; ordinary recurring-pattern questions keep their existing path. Topic, school/location, follower and contact filters remain in retrieval. Corpus retrieves the windows independently with at most 125 Normal or 500 Deep records per window (250/1,000 total), applies date/topic/profile filters before each limit, counts each clip separately and reports corpus totals independently. Relevance/ID ordering is not random or representative sampling. Deterministic counts bypass text-provider rewriting while retaining source attribution and existing access controls.
- **Separate historical proof:** the full July 8–21, 2024 source cohort has 10,957 prior-window and 11,041 current-window records. Unboxing’s share rose from about 1.2595% to 1.3948% (+0.1353 percentage points), with 93 and 104 creator identities respectively. This offline proof uses the same comparison module but is not the denominator of a smaller chat retrieval. See [RESEARCH_DATA.md](RESEARCH_DATA.md#historical-format-share-comparison) for the source/license and scope.
- **Actual bounded API/browser proof:** the no-topic July 21/7-day Deep request returned 500 records per window, three multi-creator groups and ten original source citations in about 252 ms. No group met every positive-signal threshold; Unboxing declined from 5/500 to 4/500 (−0.2 percentage points). Normal returned 125 records per window and no eligible groups; the October 17 current-date request returned zero records. The native browser rendered those actual counts/citations and retained the answer after reload without page errors. These results differ from the full historical cohort because the retrieved sample differs.
- **Current-source gap:** the bounded October 17 public [TikTok Creative Center](https://ads.tiktok.com/creative/creativeCenter/trends?deviceType=pc&locale=en&region=US) check did not acquire fresh canonical video/date evidence or cross-creator format groups. Indexed hashtag aggregates and associated display names do not close that requirement.
- **Format coverage and reference geometry (1.6.0):** default browsing reaches eligible formats beyond the first index page through at most 310 candidates and returns at most 100 unique real records. The actual browser rendered seven groups and 20 loaded covers from 86 records in 1.964 seconds; topic searches preserve combined constraints. Fifteen additional public-player metadata deltas preserved all protected fields and corpus counts, with one unavailable post unchanged. At a normalized 762px component width, measured attachment geometry differs from the launch frame by less than 0.8px; ten intermediate-desktop states and the mobile check passed. These results improve actual corpus browsing and observable fidelity without establishing current emergence or complete pixel identity.

This improves source imagery without making archival text, metrics or dates current.

`audioAvailable:false` means the vision model received no raw acoustics. A separate recognizer can still have processed audio and supplied unverified words, recorded by `transcriptProvided:true`. Music, vocal delivery, exact word timing, unseen cuts and causal analytics are not established by that pipeline.

## Completion boundary

Fictional/synthetic records, repeated rows, provider contract doubles, badges and interface labels never count as real unique indexed videos or successful real inference. Dataset licensing alone does not establish unique coverage or audiovisual/profile completeness. Local inference, model errors and missing providers are reported as observed; no fictional result substitutes for them.

Target-scale local application integration, real bounded Trends browsing, bounded archival metadata updates and source-aware composer imagery are verified. The current local demo supports tested research, briefs, compound creator filters, source playback and sampled video follow-ups; the adaptive sampler closes one reproduced blind spot. Unrestricted discovery and representative new-creator coverage, current real trends, representative audiovisual critique quality, remaining observable visual differences and matching hosted AI/coverage remain open. The full local corpus, smaller D1 deployment and exact historical publication checks are recorded separately in [VERIFICATION.md](VERIFICATION.md). Unshown private UI is an evidence boundary, not an additional invented parity requirement.
